PM Studio 的 Test Golden Case + Rubric 体系设计 & 进展

2026-05-14 对标 GDPval / 同事 Phase1-3 框架 目标 ~50 条 Golden Cases + 对应 Rubric

1我们的目标

参考 GDPval 等业界做法，为 PM Studio 产出一套针对 PM Agent 的 20-50 条 Golden Test Case + Rubric（评判标准），作为 PM Agent 能力衡量与持续迭代的"度量衡"。

2如何保证题目的权威性与真实性

不只是"让 AI 造一批题"——而是 两条独立路径同时推进，最后合在一起交叉验证，分别保证"题目该考"和"题目真实发生"。

🔼 从上往下：保证权威性

用行业先验把 PM 能力地图先画出来，作为采样配额表，确保题目来自公认标准、覆盖全面、不偏科。

⇄

🔽 从下往上：保证真实性

让大家自由提交真实工作 case，不设定方向——收集后与能力地图做匹配，看覆盖率有多高，发现哪些 cell 没人提、或哪些能力维度压根没出现在地图上，从而验证题目是否真实，也反向检验能力地图是否画全。

3如何保证 Rubric 的权威性与准确性

Rubric 的可信度由 三条彼此独立的支柱共同支撑——任何一条被质疑，另外两条都能兜底。

支柱一

横向借用内部已有框架

站在内部相邻产品已验证的 Rubric 肩膀上，不重复造轮。

支柱二

纵向锚定行业公认标准

每个评判维度都能追溯到 20 年沉淀的公开范式。

⭐ 支柱三

人工评分对比（最硬证据）

用稳定性 / 区分度 / PM 契合度三种实证验证 Rubric 和人评对得上。

支柱一：横向借用 — Edge Journeys 评测框架

Edge Journeys 团队在评判浏览器推荐功能时已搭建了一套经实战验证的评测 Rubric，我们直接横向借用其核心设计：

借用内容具体机制
四层价值链方法论"先有结构、再长维度"——从产品价值链出发派生评判维度，不拍脑袋列指标
四级答案要素结构Must include / Should include / May include / Must NOT include，结构化描述期待的回答要点

4我们和 GDPval 的差异

GDPval 的做法

GDPval 的典型流程：单轮 prompt 输入 → AI 生成实体产物（PPT / Excel / Word / 电路图等）→ 人类专家提供同等任务的真实产物作为基准 → 由 Rubric 评判 AI 产物是否优于人类产物。本质是"AI vs Human"的能力对比评估。

我们的四点核心差异

① 多轮对话，而非单轮

GDPval我们
单轮 prompt → 一个确定性产物，任务边界清晰 PM 的真实工作往往是多轮对话——澄清需求、补充信息、迭代结论——我们的 case 还原这个真实交互形态

② 评判对象不同：过程 vs 产物

GDPval我们
评判的核心抓手是最终产物——PPT 做得好不好、电路图对不对 许多 PM 任务没有实体产物（如"该不该砍这个功能"、"这个数据说明什么"）。我们的评判对象可以是对话过程本身——agent 有没有理解问题、有没有问对问题、有没有给出可执行建议

③ 过程导向：评的是"怎么想"，不只是"写了什么"

GDPval我们
Rubric 主要检查产物里有没有某项内容（content checklist） 除了内容检查，我们还评思考过程、推理链路、假设是否显式标注、结论是否有论据支撑。不是"PRD 里有没有 metrics 段"，而是"这个 metrics 为什么选它、选的是否合理"

④ 不需要人类产物

GDPval我们
必须有人类专家手工完成同等任务，才能作为对比基准 不需要人工编写 Spec 或任何对比产物。原因有二：一是没有人愿意手工写大量 case；二是我们不需要证明 AI 比人强——我们的目标是衡量 PM Agent 自身的能力水平
GDPval 评的是"AI 能不能产出和人类一样好的产物"；我们评的是"PM Agent 在真实工作对话中，能不能理解问题、想得对、过程可信"。前者是经济价值基准，后者是 PM 工作能力基准——同源方法论，不同评测目标，互不替代。

5现在的状态和接下来要做的事

5.1 关键洞察

① Asking 类是 GDPval 的盲区：PM 真实工作 40-49% 是 Asking 类（决策建议 / 诊断 / 参谋），GDPval 完全没覆盖——这是我们的差异化空间，也是我们单独设计扩展评分维度的原因。
② Management 类任务的机会窗口：Anthropic EI 显示 Management 类在 Claude.ai 8 个月内从 5% 跌到 3%——模型在这类任务上还不够好，正是 PM Agent 发力的机会。
③ 高频 ≠ 高战略权重：邮件起草是 bottom-up 第一，但 kill/scale 决策的战略价值更高。配额表把"频次"和"战略权重"分开标，避免题目被高频低价值任务淹没。
④ Rubric 不依赖人类产物也能可信：通过三支柱论证（横向借用 + 行业锚定 + 人工对比验证），Rubric 自身的可信度可以独立成立，不依赖"人类专家写同等答案"。
